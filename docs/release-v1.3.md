## 公开快照与最新实跑结论（2026-10-06）

本次更新项目理念、目标架构与示例，不进行运行时修复或新的模型试跑。
核心关系是 Codex 管理会话统筹各组主管，Dot 作为可选网关；以事件管理状态，以 N 组
实验比较业务／配置／四文档，以 LangWatch 和本地证据支持后续规则改进。
[架构与下一步验收](architecture.md)

最近一次真实会话诊断发现，以下问题仍未解决：

- 一组主管用普通文字询问是否执行，随后结束回合；被识别为空闲，未自动升级到管理会话。
- 另一组原生子 Agent 已向直接父 Agent 返回结果，但 lane 的常规决策请求出现
  `exact_recipient_missing`，未完成向组主管的往返。
- 两组主管进程登记均缺失，只有一组存在 lane 登记；影响精确收件人识别和退出核验。
  登记链路的根因仍需确认，不能把某个 PATH 假设当作已证实结论。
- 该次运行没有实际 MCP 事件订阅者；本地事件落盘不代表 Codex／Dot 收到通知或被唤醒。

用户已停止该试跑，不从发布流程恢复它。当前 `decisions.py` 只覆盖已登记 lane 与本组
主管，原生子代走 harness 返回通道；顶层统一管理关系尚未实现。这些真实失败使下方
合成回归通过的结论仅限对应组件，不能宣称待决策、权限或恢复链路已端到端可靠。
公开记录只保留一般化诊断，不分发真实会话、业务数据或私有运行标识。

本次发布检查：49 个更新文档的本地链接／标题锚点有效，114 个公开文件哈希一致，
四份执行正文未改动；公开文件的敏感路径和常见凭据格式扫描未发现匹配。
`start-claude.sh --check` 确认配置与四文档哈希匹配，未调用模型；Git 空白检查通过。
这些是文档与打包检查，不是业务或消息链路的端到端验证。

## 本机派发阻断修复（2026-10-05）

首次 Dot 双组试跑在发送前把 `agent read` 的文本按 JSON 解析，两个组均阻断。
已修复：读屏显式使用 text，结构化命令严格解析 JSON；错误记录操作名及安全错误码，
不把任务内容或凭据带进报错。发送前核对与发送尝试、提交成功分别记录，结果未知不重试。
`needs_attention` 仍执行到期停止检查，停止最多尝试一次；UI 总状态明确显示待核对。
workspace 创建传入完整主管环境，包括精确 session ID 和遥测角色。

真实 Claude 2.1.290 的空输入底栏有 `⏵⏵`，也已加入有限识别规则。
实验环境设置 `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false`，避免灰色建议与真实草稿混淆；
这是[官方支持的会话环境设置](https://code.claude.com/docs/en/env-vars)，不改全局偏好或权限。
用户草稿、未知屏幕及权限弹窗仍拒绝自动输入；新建不受信任仓库的验证确实被阻断，未代答。

已经存在且权限正确的私有状态目录不再重复 mkdir/chmod，避免 Dot 的只读状态查询
无端要求工作区外写权限；实际启动仍遵循本机权限边界。

验证：41 项实验模块测试通过（含文本读取、真实底栏形状、发送前失败与发送结果未知、
待核对状态超时、主管环境传递）。在独立真实 Herdr 0.9.0 中启动 Claude 2.1.290，
使用既有已信任 checkout、新 UUID，只发送本地 `/help`；实际看到 Help / General /
Commands 界面，读取与提交均通过，随后关闭测试 pane/session，checkout 保持不变。
没有发送业务模型任务，因此尚不证明业务端到端完成、服务端模型接受或实际账单。

## 双组完工后的收尾修复（2026-10-05）

真实双组已进入开发并产生提交，暴露了验收路径错误、DONE 未唤醒主管、隔离目录探针
拒绝，以及超时只能中断主管的问题。本补丁修复平台协议，业务结果与旧快照保持原样。

- 开工前检查验收可执行文件；POSIX `test` 的系统路径差异按本机解析，原 argv 和实际 argv
  同时留证。命令消失/执行失败记入验收结果，不丢成无细节的异常，不自动重复验收。
- 现有 dispatcher 读取已登记 lane 的 DONE 与完整回合证据，去重后仅调用原 `--resume`。
  空闲未完成的 lane 每会话保留一次 15 分钟兜底。新实验不叠加终端 notify-back、后台等待
  或模型定时器；历史文档保留其旧传输，不混搭。用户草稿/弹窗仍阻止输入，绝不自动清空。
- 业务指令提交等待 Herdr 观察到 `working`；结果不确定不重发，继续只读观察以接收迟到结果。
- 探针根据冻结 context 验证本组 checkout/lanes；仍拒绝跨组、篡改哈希和逃逸路径。
- wrapper 在 exec 前登记 PID、启动时间、session 和组身份。调度器记录原生进程后代，
  完工/到期按归属做有限 TERM/KILL，并核验退出才释放槽位；不按进程名或端口批量杀进程。
  未登记的历史进程、身份不明和停止失败留为待核对，不冒充成功，也不是账户总费用上限。
- 页面分别显示交付报告、独立验收、资源收尾和原始错误。旧 dispatcher 或服务启动后
  代码变化会阻止新派发，要求冷启动；不会把旧会话宣称成已升级。

验证通过：58 项实验模块测试、63 项既有观测/遥测/探针回归；浏览器 1280/768/360 宽度
与三组状态展示通过，零模型调用。使用合成任务、真实本机父子进程；覆盖重复/不确定通知、输入草稿、
跨组拒绝、PID 复用、外部进程保留、验收失败与清理后释放槽位。付费模型端到端重测尚未进行；
原生子代理日志仍按精确父会话读取，可见部分与完整覆盖分别报告，未知账单不补估。

## 决策往返与默认子代上限（2026-10-05）

上一补丁只覆盖 DONE/空闲通知，不能证明任意待决策问题已传给上级。此次在原四文档
任务书和 driver §6g 内补上 `parent-v1`：登记 lane → 本组主管读取并答复 → 原 lane 单次接收。
复用现有 dispatcher/CLI，不增角色、模型巡检或另一套提示词系统。新默认原生子 Agent
并发 3、深度 3；组数、lane 数和原生并发分别控制，历史实验及固定上限快照不改。

PID/启动时间、Herdr session/pane、Claude 当前 session/cwd、冻结哈希共同验证收发身份；
问题与答复有不可替换哈希、去重键、截止时间和分段回执。草稿/权限窗口不覆盖，未知发送
不重复，未接收的决策阻止完成验收但不阻止到期收尾。界面展示各阶段与原始传输错误。
原生子 Agent 的上报使用 Claude 自带结果通道，由直接父 Agent 决策或继续升级；本模块
不伪造原生子代身份，也不自动批准权限、范围或预算，更不冒称已经接通 Dot 云端事件唤醒。

验证使用合成会话、真实本机进程与本地 UI，不调用业务模型。付费模型的往返、原生子代
返回及两组业务完成留给全新隔离试跑；只有各跳真实回执及后续业务证据齐备才能算通过。
72 项实验回归、61 项遥测/观测/探针回归通过；三组配置与决策状态页面在 1280/768/360
宽度通过浏览器检查。新试跑另外把决策完整回执作为共同验收，不能只凭业务测试判成功。
